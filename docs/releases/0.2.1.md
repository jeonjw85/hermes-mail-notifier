# 0.2.1 acceptance record

Date: 2026-11-03. Status: **local verification passed with two host-dependency gaps; live-server qualification pending**. No release tag was published.

## Product changes

- Rejected input no longer discards the Telegram setup panel. A single invalid value previously raised past the controller and replaced the whole panel with `Could not finish: invalid_settings`, losing the prompt. The bound prompt is now re-shown with `Check input: ... Try this field again.` and the same reply can be corrected in place.
- Duplicate-account rejection (`account_already_exists_use_edit`) now behaves the same way instead of ending the panel.
- Naver/Daum bare login IDs are accepted. Telegram previously required a full `id@domain.tld` address while the CLI and settings validator already accepted a bare ID, so a valid Naver ID was rejected with `invalid_settings` only on Telegram.
- Development dependency pins were relaxed to `ruff>=0.15.10,<0.18` and `pyright>=1.1.414`.

## Included since the 0.2.0 acceptance record

The 0.2.0 record stated that no release was published. The authenticated Telegram onboarding feature set completed after it had therefore never been versioned separately; it ships here for the first time:

- `/mail` onboarding bound to the authenticated private chat, with Naver/Daum/Gmail selection.
- Encrypted Mini App credential input on an operator-configured trusted HTTPS page; passwords are never accepted as chat text.
- Recoverable setup drafts with durable write markers, interruption repair, conflict review and explicit acknowledgement.
- Non-secret account, policy, schedule, language and recovery management from Telegram.
- Korean/English UI and message catalogs; pinned-host admission and contract tests.

No settings or database schema changed in 0.2.1. Existing schema 3 databases and settings schema v2 are unchanged.

## Upgrade

1. Restart the Hermes gateway so the updated plugin module is loaded.
2. Run `hermes mail-notifier status --json` and `doctor --json`. Schema, account checkpoints and the owned cron job are unaffected by this version.
3. Send `/mail` in the bot's private chat. A draft interrupted by the previous `invalid_settings` error is preserved and re-opens at the same input prompt.
4. For a Naver or Daum account, enter the login ID exactly as used for web login (`myid`, not necessarily an address). For Google, use the full address.
