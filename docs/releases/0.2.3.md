# 0.2.3 acceptance record

Date: 2026-11-04. Status: **all CI gates reproduced locally against the pinned host; released as tag `v0.2.3`; live-server qualification pending**.

## Why this release exists

A setup confirmation failed with `오류: model_unavailable` and advice to check `model.provider` and its API key, on a host whose model was answering normally. The advice could not be right for every case, because the code covered too many different failures.

Two defects produced that:

1. **Every failure inside a model call collapsed into one code.** `complete_structured` caught bare `Exception` and raised `model_unavailable`. "No provider configured", "this provider has no credentials", "the credential pool is out of credits", "the credential is rate-limited", "the model name does not exist" and "the installed Hermes does not have this API" all became the same message. They need completely different fixes, so the advice was wrong in four of six cases.

2. **A host API mismatch was reported as a model failure.** The plugin is written against a specific host revision. On any other Hermes revision where `ctx.llm.complete_structured` is missing, renamed, or has different keywords, the call raises `TypeError`/`AttributeError` — which the catch-all rewrote to `model_unavailable`. The user is then sent to fix a model provider that is working, instead of being told the plugin does not match the host.

## Product changes

- `ModelUnavailable` now carries a specific code:
  - `model_not_configured` — no provider selected in this profile
  - `model_auth_failed` — provider set, credentials missing or rejected
  - `model_out_of_credits` — quota or credits exhausted
  - `model_rate_limited` — temporary 429 / cooldown
  - `model_not_found` — the configured model name is not served by that provider
  - `model_unavailable` — anything genuinely unclassified
- A call-boundary `TypeError` (wrong keywords or arity) and a missing facade now raise `incompatible_hermes`, naming the plugin/host mismatch instead of the model. A `TypeError` raised *inside* the host still counts as a model failure, so real host faults are not mislabelled the other way.
- Each new code has bilingual guidance with the command that actually applies (`hermes model`, `hermes auth`, `hermes setup`, billing, waiting for a reset).
- Provider text is still never copied into a code, a message or the recovery record; classification reads the exception only to choose a code.
- `tests/test_error_codes.py` grew a second guard: codes selected from a lookup table are invisible to the raise-site scan, so the table is checked against the durable allowlist directly.

## Upgrade

1. Restart the Hermes gateway so the updated plugin module is loaded.
2. Send `/mail` and confirm again. The preserved draft needs no account re-entry.
3. Read the new code instead of the old blanket one:
   - `incompatible_hermes` → update the plugin or the host to a matching revision.
   - `model_not_configured` → `hermes setup` or `hermes model`.
   - `model_auth_failed` → `hermes auth`, or save that provider's API key.
   - `model_out_of_credits` → check billing, or `hermes model` to switch.
   - `model_rate_limited` → wait for the reset, or `hermes auth add`.
   - `model_not_found` → `hermes model` to pick a model the provider serves.
