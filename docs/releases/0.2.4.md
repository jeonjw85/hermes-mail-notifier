# 0.2.4 acceptance record

Date: 2026-11-04. Status: **all CI gates reproduced locally against the pinned host; released as tag `v0.2.4`; live-server qualification pending**.

## Why this release exists

0.2.3 made a host API mismatch visible as `incompatible_hermes`. That was honest but still wrong: an open-source plugin cannot ask every installer to pin one host revision. The plugin should adapt to the host it finds.

Two things followed from that:

1. **Optional keywords were sent unconditionally.** `complete_structured` always passed `timeout`, `max_tokens` and `purpose`. A host revision that named them differently, or did not have them yet, rejected the whole call — and the reply the plugin needed was one keyword away.
2. **The structured method was treated as mandatory.** `check_compatibility` required `ctx.llm.complete_structured`, so a host offering only `ctx.llm.complete` was ruled out entirely. The plugin already validates the schema itself in `triage_message`, so structured support was never required — only convenient.

## Product changes

- The host's signature is inspected before the call; only keywords it accepts are sent. When a signature cannot be inspected, the call falls back to positional-free minimal arguments rather than assuming support.
- If no structured method exists, or its signature is not usable, the plugin calls `ctx.llm.complete`, renders the instructions and JSON schema into one message, and parses the reply locally — tolerating a fenced ```json block.
- Unparseable text raises `invalid_model_output`, so the existing retry and review-notification behaviour is unchanged.
- `check_compatibility` accepts a host with either method.
- `incompatible_hermes` is now reserved for a host that has neither, which is the one case the plugin genuinely cannot serve.
- Result shapes are read tolerantly: a bare string, an object with `text`, or an object with `parsed` all work, and usage fields stay optional.

Verified against three host variants built for this test — a structured-only host with the older signature, a text-only host, and a host with both — plus the real pinned revision. All four return a parsed reply.
